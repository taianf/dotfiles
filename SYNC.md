# SYNC.md — Dotfile sync workflow

This repo's dotfile workflow is **live wins, repo mirrors**. You edit
files in their normal XDG locations (or `~/.zshrc`); a systemd path
unit watches for changes and auto-commits them to the repo.

## TL;DR

```bash
# Edit any file under ~/.config/ or ~/.zshrc — it auto-commits within
# seconds. That's the whole workflow.

# If you want to push to remote:
cd ~/dotfiles && git push

# If you want to manually trigger a sync (e.g. for a file outside the
# watched paths):
~/dotfiles/bin/sync-dotfiles
```

## The two halves

| Direction | Trigger | Tool | What it does |
|---|---|---|---|
| Live → repo | systemd path unit watches `~/.config` | `bin/sync-dotfiles` | `rsync` with excludes → `git add -A` → `git commit` → `git push` |
| Repo → live | `default.target` on boot | `bin/sync-dotfiles-on-boot` | `git pull --rebase` → `cp -r` for files missing in live (additive only) |

**Live always wins.** If a file exists at `~/.config/foo` and also at
`~/dotfiles/config/foo`, the live file is canonical. The boot-time
pull will *never* overwrite it. New files added in a commit *do*
appear in `~/.config/` on next boot, because the live file is missing
in that case.

## First-time install (fresh machine)

`home.activation.seed-dotfiles` (in `home/programs.nix`) handles
this. On first activation, it runs after `writeBoundary` and copies
each tracked file from `~/dotfiles/config/` to its live location,
**only if the live file doesn't exist**. Existing user edits
(including edits made between `git clone` and first `home-manager
switch`) are preserved.

The seed is idempotent — re-running it on every activation is a no-op
once the live files exist.

## What gets synced

The `bin/sync-dotfiles` rsync mirrors `~/.config/` to
`~/dotfiles/config/`. A few files outside `~/.config/` are handled
explicitly:

| Live | Repo |
|---|---|
| `~/.zshrc` | `config/zsh/.zshrc` |
| `~/.config/zed/settings.json` | `config/zed/settings.json` |
| `~/.config/ghostty/config` | `config/ghostty/config` |
| `~/.config/topgrade.toml` | `config/topgrade.toml` |
| `~/.config/opencode/...` | `config/opencode/...` |
| `~/.config/autostart/ferdium.desktop` | `config/autostart/ferdium.desktop` |
| `~/.config/cosmic/.../keyboard_config` | `config/cosmic/.../keyboard_config` |

To add a new file: commit it to `config/`, then add a corresponding
`seed` line in `home.activation.seed-dotfiles` and a `deploy` line in
`bin/sync-dotfiles-on-boot`.

## What doesn't get synced

`.sync-ignore` lists the rsync exclude patterns: locks, IPC sockets,
caches, swap files, per-machine `.local` overrides, etc. These are
generated by programs at runtime and would create spurious commits if
mirrored.

## Common workflows

**Edit a config:** open the file at its live path, save. Watch
`~/dotfiles` for the auto-commit, then `git push` when you're ready.

**Add a new tracked config:**

1. Edit the live file (e.g. `~/.config/alacritty/alacritty.toml`).
2. Wait for `bin/sync-dotfiles` to mirror it to
   `~/dotfiles/config/alacritty/alacritty.toml` and auto-commit.
3. Push: `cd ~/dotfiles && git push`.

**Add a tracked config to a new machine:** just clone the repo and
run `nixup`. The seed-dotfiles activation will copy the configs into
`~/.config/`. Then the path unit takes over and keeps them mirrored.

**Discard live edits and reset to repo:**

```bash
cp -r ~/dotfiles/config/zed/settings.json ~/.config/zed/settings.json
```

(Or `git checkout` in the repo and re-sync.)

## When this doesn't apply

- Program-managed dotfiles that the user is OK with HM regenerating
  every `nixup` (e.g. some NixOS system configs). Those stay in Nix.
- One-off, machine-specific config. Use `*.local` files (gitignored
  via `.sync-ignore`) or put them outside the watched paths.
- Secrets. Use `sops-nix` (`nixos/sops.nix`, `secrets.yaml`).
